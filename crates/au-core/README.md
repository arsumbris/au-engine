# au-core

Type-graph, closure resolution, validation, candidate scanning. The load-bearing crate.

The validator is pure: `(graph, file) → Report`. No I/O. The graph is immutable after load.

## Modules

- `typedef` — type-def AST + structural parser. `parse_type_def(path, source, yaml_offset, doc) → ParseResult`. Each FieldDecl carries `parsed_shape: Result<Shape, Diagnostic>` (au-grammar parses once at load; Errs surface lazily at instance-validation time). `MetaBlock` carries the sub-region body as `fields: Vec<InstanceField>` so meta-body validation reuses the same per-field machinery as inline values. `TypeDef.meta_blocks: Option<Vec<MetaBlock>>` distinguishes absent `meta:` (None) from suppression (`Some(vec![])`).
- `instance` — instance AST + structural parser. `parse_instance(path, source, yaml_offset, doc) → InstanceParseResult`. Includes the reserved-key-on-instance check. `InstanceValue::Sequence(Vec<SequenceElement>)` carries per-element spans for elementwise list-validation diagnostics. `InstanceValue::Mapping(InlineValue)` carries an inline value — a YAML map mirroring file frontmatter (`type_claim: Option<TypeClaim>`, `block_id: Option<BlockIdDecl>` for the `^:` addressability key per [[type block-id::au-type-system]], plus arbitrary fields); the recursive classifier handles nested inline values transparently. A top-level `^:` warns (`block-id-on-instance-root`); a malformed `^:` value errors (`block-id-malformed`).
- `graph` — `TypeGraph`: BTreeMap-backed, deterministic iteration. `build_graph(Vec<TypeDef>) → GraphBuildResult`.
- `load_checks` — `run_graph_structure_checks` (regex, duplicate meta, cycles, reserved type-def names — `file` plus the six primitive shape names `String`/`Number`/`Boolean`/`Date`/`DateTime`/`Url`, slot-reference-targets-exist, slot-union and slot-intersection subsumption covering both subtype-by-closure and cardinality-refinement cases) and `run_inheritance_checks` (redeclare, sealed reachability, type-def-level `mixin-collision` on multi-parent claims, plus the shared `check_redundant_claims` helper that emits `duplicate-claim` and `subsumption-in-mixin` warnings on type-def parent lists).
- `closure` — `closure_of(graph, name)` and `effective_shape(graph, claim) → Result<EffectiveShape, EffectiveShapeError>`. Multi-claim mixin unions every claim's closure into `instance_closure`; auto-unifies fields whose `parsed_shape` is token-equal across origins (one entry, multi-origin); surfaces non-token-equal collisions on `EffectiveShape::collisions()` separately so the validator's per-field path stays branch-free on the happy path. `FieldOrigin.origins: BTreeMap<TypeName, OriginInfo>` preserves per-origin `decl.optional` so the per-originator required-field rule can iterate per-slot without losing optional bits.
- `validate` — pure `validate(ctx: &ValidateContext, instance) → Vec<Diagnostic>` plus `validate_meta_bodies(ctx) → Vec<Diagnostic>`. Covers single-claim and multi-claim mixin instances; primitive shapes (including `Url` with `^https?://` check), inline closed enums, typed references (`name*` including built-in `file*`), bare-name records (`name`, inline-only), inline-or-reference (`name&`, inline-or-wikilink), and list shapes (`X[]` with elementwise validation through nested lists, plus the non-empty variant `X[+]` which rejects empty sequences); compound shapes: Union (any-of) emits ONE `field-shape-mismatch` if no branch validates, Intersection (all-of) concatenates per-branch failures, `<...>*` CompoundReference resolves the wikilink once and op-aware-walks the target's closure across branches, `<...>&` accepts inline maps or wikilinks; inline-value `type:` disambiguation's four cases (`InlineCompat::SingleDemand` / `Union` / `Intersection`); `<String | T*>` wikilink-pattern routing, plus `<String | Url>` `^https?://` routing (the prefix commits prefix-shaped values to the Url branch); qualified field keys (`field{T}` resolves to the field's originator via `closure_of(T)`); per-originator required-field-absent; `mixed-bare-and-qualified-field` for contradictory-form fields; redundant-claim warnings (`duplicate-claim`, `subsumption-in-mixin`) on instance claim lists; sealed-family per-claim exhaustiveness — `sealed-parent-claimed` fires on each claim element (file-level, inline, or meta site) naming a sealed type-def; multi-leaf-in-sealed-family — `multi-leaf-in-sealed-family` fires once per violated sealed family when one claim list carries two or more distinct non-sealed leaves of it (innermost-only suppression on nested sums; symmetric at file-level and inline-value identity claims via the `check_multi_leaf_in_sealed_family` helper); `validate_meta_bodies` walks every TypeDef's `meta_blocks` and validates each block against the named meta-type-def via a parallel `validate_meta_subregion` helper.
- `meta` — consumer walk helper. `lookup_meta(graph, resolution, host, meta_type, meta_repo) → Option<&MetaBlock>` traverses `host`'s `type:` chain ancestors and returns the first matching sub-region. With a resolution graph it walks the folded closure, so a `::repo` parent's `meta:` is inherited cross-repo (parity with `location`); without one a `::repo` parent is skipped. Respects suppression (`meta: []` halts the walk) and does not recurse into encountered meta-type-defs' own metas. Termination is bounded by the `cycle-in-type-chain` load check.
- `candidates` — implicit identity candidate scan. `scan_top_level(graph, instance) → Vec<Candidate>`; `scan(graph, instance) → Vec<Candidate>` combines top-level + nested into one ranked list. Walker threads the host closure through recursion so unclaimed inline values (case 1) resolve via the surrounding slot's demanded type-def. "Fully satisfied" is shape-aware: each required field must be present AND its value must conform to T's declared shape (primitive type, enum membership, list cardinality including `[+]`, value-shape category); reference-resolution stays permissive. Filters sealed parents (unactionable); for sibling-leaf candidates under an already-claimed sealed family, `Candidate.supersedes: Vec<TypeName>` names the leaves that would need to be dropped first (multi-leaf-in-sealed-family). `CandidateScope` carries an RFC 6901 JSON Pointer (`""` for top-level, `/rationales/0/evidence/1` for nested). Advisory output — never validates or invalidates.
- `codes` — kebab-case `DiagnosticCode` constants emitted from this crate. Mixin / field-qualifier codes: `mixin-collision`, `duplicate-claim`, `subsumption-in-mixin`, `malformed-qualifier-key`, `qualifier-not-in-closure`, `qualifier-does-not-declare-field`, `mixed-bare-and-qualified-field`. Sealed-family codes: `sealed-parent-claimed`, `multi-leaf-in-sealed-family` (fires when one claim list carries two distinct non-sealed leaves of the same sealed family; symmetric at inline-value identity claims). Compound-shape codes: `subsumption-in-slot-union` and `subsumption-in-slot-intersection` (symmetric to `subsumption-in-mixin`). Inline-value codes: `inline-value-missing-type`, `inline-value-type-not-compatible`. Meta-side code: `meta-mixin-not-supported` (parse-time).
- `body` — body-typing v5 type-def template AST + recursive YAML parser. `BodyItem::{Use, Section, Fills}` discriminator-keyed items; `FillsContract` carries `fields` + `exclusive` flag. `is_body_declaring(body) → bool` checks the format-coupling predicate.
- `provenance` — per-field effective values with provenance. `effective_values(instance, body_events, body_offset) → BTreeMap<FieldName, Vec<ValueContainer>>`. `Surface::{Frontmatter, BodyWikilink, BodyYamlBlock, BodyInlineCode}`; `ContributionValue::{Scalar, Reference, InlineRecord}`. Equal values across surfaces collapse to one container; ordering follows source-position. Null frontmatter values are visibility markers (not value contributions).
- `record_targets` — per-file index of addressable inline records per [[type block-id::au-type-system]]. `collect_record_targets(graph, instance) → RecordTargets` maps each `^:` id to its `RecordTarget` (effective claim names, explicit or slot-pinned, plus the id's span). Reference resolution checks records first (frontmatter precedes the body), body blocks second.
- `body_validate` — per-instance body-typing checks. `validate_body(ctx, instance, body_source, body_offset, is_markdown)` runs: format coupling, section presence, fills contracts (with exclusivity propagation), cross-surface cardinality, frontmatter visibility, per-contribution shape and unbound-field-binding checks (block-id resolution gated to reference-admitting slots), malformed-marker detection, body wikilink fragment-order checks, marked-fence required-field check; `block-id-duplicate` spans one namespace per file across body markers and record `^:` ids. Frontmatter-side `^block-id` reference resolution lives in `validate` (slot-gated, records and typed blocks, the local `[[^id]]` / `[[#head]]` forms). Wired into `au_engine::build` after the per-instance `validate()` pass. Body-typing codes: `body-required-but-yaml-only-instance`, `body-section-missing`, `body-section-out-of-order`, `body-unterminated-fence`, `block-id-duplicate`, `fills-contract-unmet`, `fills-contract-exceeded`, `body-fills-without-frontmatter-key`, `field-cardinality-exceeded`, `unbound-field-binding`, `body-slot-shape-mismatch`, `unknown-field-in-prose-contribution`, `malformed-attribution-marker`, `block-id-not-typed`, `block-id-not-found`, `embedded-record-validation-failure`. Load-time companions in `load_checks::run_body_typing_checks`: `body-use-out-of-closure`, `body-use-cycle`, `body-use-nested`, `fills-unknown-field`, `fills-contract-conflict-nested-exclusivity`, `fills-double-form-declaration`.

The validator special-cases `InstanceValue::Null` as the "filled by body" visibility marker — `check_value_against_shape` accepts null without shape-mismatch, leaving the absence (or presence) determination to higher-layer body checks.
